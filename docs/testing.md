# テスト実行ガイド

このプロジェクトには、コードの品質を維持し、パイプラインが正しく動作することを確認するためのいくつかのテストが用意されています。

## 1. Lint (静的コード解析)

コードのスタイルや潜在的なバグをチェックします。`ruff` という高速なリンターを使用します。

### 実行方法
プロジェクトのルートディレクトリで以下のコマンドを実行します。

```bash
ruff check .
```

### 自動実行
このチェックは、GitHub ActionsのCIワークフローに組み込まれており、Pull Request作成時などに自動的に実行されます。

## 2. Unit Test (単体テスト)

個々の関数やモジュールが正しく動作するかを確認するためのテストです。フレームワークとして `pytest` を使用します。

*(注: 2024年8月現在、具体的なテストケースはまだ実装されていません。以下は、将来的にテストケースを追加した際の実行手順です。)*

### 実行方法
プロジェクトのルートディレクトリで以下のコマンドを実行します。

```bash
pytest
```
`pytest` は `tests` ディレクトリ（まだ作成されていません）などから `test_*.py` という命名規則のファイルを見つけて自動的に実行します。

### CIでの実行
このコマンドもCIワークフローに組み込まれており、JUnit XML形式のレポート (`pytest-report.xml`) を生成します。

## 3. CI Integration Test (CI向け連携テスト)

CI環境で安全に実行できる、ローカル完結の連携テストです。クラウドサービスへの接続など、外部の秘密情報に依存しない部分のパイプラインを検証します。

**テスト内容:**
- サンプルJSONデータをChromaDBに登録 (`embed_and_upsert.py`)
- 登録したデータに対して、意図した結果が返ってくるかをローカル検索で確認 (`verify_search.py`)

### 実行方法
- **Linux / macOS / WSL の場合 (Bash):**
  ```bash
  ./scripts/ci_test.sh
  ```
このテストはCIワークフローの中心的な役割を担っており、Pull Requestのマージ前に必ず成功している必要があります。

## 4. End-to-End (E2E) Test (総合テスト)

実際の運用とほぼ同じ流れで、パイプライン全体が正しく動作するかを検証する総合テストです。
このテストは、クラウドサービス (Firebase, Notion) への実際の接続を含むため、**ローカル環境でのみ実行してください。**

### 前提条件
- [セットアップガイド](./setup.md) に従って、すべての環境設定が完了していること。
- 特に、Firebaseのサービスアカウントキー (`serviceAccountKey.json`) の配置と、Notionの環境変数 (`NOTION_API_TOKEN`, `NOTION_DATABASE_ID`) の設定が必須です。
- Firebase CLIにログインしていること (`firebase login`)。

### 実行方法
- **Windows の場合 (PowerShell):**
  ```powershell
  .\scripts\e2e_test.ps1
  ```
- **Linux / macOS / WSL の場合 (Bash):**
  ```bash
  ./scripts/e2e_test.sh
  ```

### 注意点
- このテストは、**実際にFirestoreとNotionにテストデータを作成します。**
- テストスクリプトは、成功時にFirestoreのテストデータを自動で削除しようと試みます。
- Notionに作成されたテストページは、**手動で削除する必要があります。**
