# 運用マニュアル (Runbook)

## 🎯 このマニュアルの目的
このドキュメントは、`PixelRecordings-Analytics` プロジェクトの日常的な運用手順を説明します。
新しい会議の録音データをシステムに取り込み、分析・閲覧可能な状態にするための、**単一の自動化コマンド**について解説します。

## ✅ 1. 始める前に (前提条件)
このマニュアルを実行する前に、**[プロジェクトセットアップガイド](./setup.md)** の手順がすべて完了している必要があります。

特に、以下の点が満たされているか確認してください。
- ✅ Python, rclone, whisper.cpp などのソフトウェアがインストール済み
- ✅ Pythonの依存関係がインストール済み (`pip install -r ...`)
- ✅ Firebase と Notion の認証情報が正しく設定済み

## 🚀 2. 自動化パイプラインの実行

新しい会議データを処理するためのすべてのステップ（同期、文字起こし、DB登録、クラウド同期）は、以下の単一のコマンドで自動的に実行されます。

### 実行コマンド
プロジェクトのルートディレクトリで、以下のコマンドを実行してください。

```bash
python scripts/run_pipeline.py
```

### Google Driveとの同期も同時に行う場合
`--sync-first` オプションを追加すると、処理の開始前にGoogle Driveから最新のファイルをダウンロードします。

```bash
python scripts/run_pipeline.py --sync-first
```

### 処理の流れ
このコマンドを実行すると、内部的に以下の処理が自動で行われます。
1.  (オプション) Google Driveからローカルにファイルを同期します。
2.  `local_data/recordings` ディレクトリをスキャンし、まだ処理されていない新しい音声ファイルを検出します。
3.  新しいファイルが見つかった場合、ファイルごとに以下の処理を順番に実行します。
    - 文字起こし (`transcribe_whisper`)
    - 埋め込みとChromaDBへの登録 (`embed_and_upsert`)
    - Firestoreへのメタデータ同期 (`sync_to_firestore`)
    - Notionへのページ作成 (`sync_to_notion`)
4.  最後に、どのファイルが成功し、どのファイルが失敗したかのサマリーが表示されます。

### 期待される結果
- コンソールに処理の進捗がリアルタイムで表示されます。
- すべての処理が完了すると、成功・失敗のサマリーが表示されます。
- 成功したデータは、WebアプリやNotionで確認できるようになります。

## ❓ 3. トラブルシューティング
- **問題:** パイプラインの途中でエラーが発生した。
  - **解決策:** コンソールに出力されるエラーメッセージを確認してください。`Stderr:` の部分に、失敗したスクリプトからの詳細なエラー内容が出力されます。多くの場合、認証情報（Firebase/Notion）の設定ミスや、`whisper.cpp`のパス設定などが原因です。詳細は **[セットアップガイド](./setup.md)** を再確認してください。

- **問題:** 新しいファイルが処理されない。
  - **解決策:**
    1. `python scripts/run_pipeline.py --sync-first` を実行して、ファイルが正しくローカルに同期されているか確認してください。
    2. `local_data/recordings` と `local_data/transcripts` の内容を見比べて、ファイル名（拡張子を除く）が一致するJSONファイルがすでに存在しないか確認してください。すでに存在する場合、処理済みと見なされます。

## 🔎 3. データの閲覧と検索

パイプラインで処理したデータは、PWA（Webアプリ）を通じて閲覧・検索します。

### ステップ 1: ローカル検索APIを起動する
**目的:** PWAからの検索リクエストに応答するための、バックエンドサーバーを起動します。
**このターミナルは、検索機能を使っている間は起動したままにしてください。**

- **OS共通:**
  ```bash
  # プロジェクトのルートディレクトリで実行
  uvicorn services.api.app:app --reload
  ```
**→期待される結果:** サーバーが起動し、`Uvicorn running on http://127.0.0.1:8000` のようなメッセージが表示されます。

### ステップ 2: Webアプリで確認
**目的:** 同期したデータが、スマートフォンやPCのブラウザから正しく閲覧・検索できるか最終確認します。

1.  **(初回のみ) Firebase HostingにPWAをデプロイ:**
    ```bash
    firebase deploy --only hosting
    ```
2.  **アプリを開く:**
    デプロイ時に表示される **Hosting URL** にブラウザでアクセスします。
3.  **確認:**
    - **一覧表示:** 会議が一覧に表示され、クリックで詳細が展開されるか確認します。
    - **検索機能:**
        - **ステップ1のAPIサーバーが起動していることを確認してください。**
        - 上部の検索バーにキーワード（例: 「予算」「次のステップ」など）を入力してSearchボタンを押します。
        - すべての会議から、関連する発言が類似度順にリスト表示されるか確認します。
        - **検索結果の項目をクリックすると、その発言が含まれる会議の全文が表示され、該当箇所がハイライトされることを確認します。**
        - 「Show All Meetings」ボタンで全件表示に戻るか確認します。
